Stamp a document

Your private key is made and kept on this device, or stays elsewhere: in a Nostr signer app, offline, or on another device. The document is read here, and uploaded only if you tick the boxes that make it public. The seal records the time between two Bitcoin blocks.

1Your seal

Your seals on this device

Your seal is a key pair and the artwork in its center: a private key that signs, which only you hold, and its public key, which anyone can use to check what the private key signed. Make them here, use a private key you keep elsewhere (in a Nostr signer app, offline, or on another device), or open a private key file you saved before.

This is how your seal will look. The dots in the ring change with every document.

Your private key stays off this page: in a Nostr signer app or browser extension, offline on your own computer, or on another device. This page asks for a signature each time it needs one.

Or type your public key and sign codes yourself: offline with the DigiHan Python tools, or on another device that holds your private key.

Sign this code with your private key, kept offline. The code is the SHA-256 hash (32 bytes) of your seal's public record, which ties your artwork to your public key. The record holds your public key, the time, your public key id (the first 8 bytes of your public key's SHA-256 hash) and your artwork's SHA-256 hash. The code is also the record's Nostr id.

With the DigiHan Python tools: python sign_hash.py CODE --key YOUR_KEY (YOUR_KEY is your private key file; it asks for its password). Any BIP340 signer works if it signs the 32 bytes exactly as given. A tool that hashes the code again, or uses Bitcoin's older signed-message method, gives a signature this page will not accept. Sign only codes this page shows you: a signature over a code counts as a signature over whatever made it.

On the device that holds your private key, open this page, pick that seal and tap “Sign for another device”. Scan this code with it, then scan its answer here.

Your name

A scanner shows a name with your seals only when your own website confirms it. The name goes into this public key's Nostr profile (NIP-05, like you@yourdomain.com), and your website lists this public key under it in a small file. Without a confirmed name, scanners show your seals as signed by a public key they do not know.

Your website must send this file itself, with no redirect, and with the header Access-Control-Allow-Origin: *, so that scanners in a browser are allowed to read it.

2Your document

Any file: a PDF, a picture, a spreadsheet. You get back a stamped PDF: the seal on its first page, then your document to read (a PDF's own pages, or the text or picture of a text file or picture), with your original file attached unchanged. Other kinds of file, such as spreadsheets, are attached only.

This photo carries the place it was taken. The stamped file keeps it, and so will any public copy.

    Sign this code with your private key, kept offline, then paste the signature. The code is one SHA-256 hash (32 bytes) made from: this document's SHA-256 hash; the time, or the Bitcoin block number if you chose the block proof; your public key id; your artwork's SHA-256 hash; and, with the block proof, the block's hash. The signature goes into the seal's ring.

    With the DigiHan Python tools: python sign_hash.py CODE --key YOUR_KEY. Sign only codes this page shows you.
